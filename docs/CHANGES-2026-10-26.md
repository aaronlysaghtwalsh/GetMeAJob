# Changes on 26 October 2026: test compatibility and type fix

Made by Claude while preparing the project for a portfolio demonstration. A backup of the project as it was before these changes is in `../backups/getmeajob-backup-2026-10-26-before-portfolio-fixes.zip`, with `BACKUP_MANIFEST.txt` listing every file's hash and original modification time.

No functionality was removed, the live-API behaviour is unchanged, and nothing in `data/` was modified.

## 1. Test compatibility with the 7 October structured-output change

**Problem.** On 7 October, `src/server/ai/service.ts` was changed so that five tasks (resume extraction, job analysis, research structuring, fit analysis, strategy) no longer use native structured outputs. Instead, the JSON Schema goes into the instructions. The app's own AI-call log shows why: in live use, the Anthropic API rejected these requests with "The compiled grammar is too large". After the change, those calls succeeded.

The change worked for live use but broke test mode. The scripted test provider chose its fake response by the schema name sent with native structured outputs (`req.jsonSchema.name`). For the five tasks no schema was sent, so the provider had no response to return, and 10 of 22 tests and the browser walkthrough failed.

**Fix (keeps the live-API change).**

- `src/server/ai/types.ts`: added an optional `schemaName` to `ProviderRequest`. This is internal metadata; the Anthropic and OpenAI providers never send it.
- `src/server/ai/service.ts`: every structured call now sets `schemaName`. The list of five tasks moved, unchanged, into a named constant, `PROMPT_SCHEMA_TASKS`, with a comment explaining the API error. Indentation was corrected. Behaviour is identical.
- `src/server/ai/scripted.ts`: the test provider falls back to `req.schemaName` when no native schema is sent.
- `tests/integration/pipeline.test.ts`: new test that these five tasks send no native schema and carry the schema in their instructions, while other tasks (for example the resume) still use native structured outputs. It fails if the workaround is removed, so a future change cannot silently undo the live-API fix.

## 2. TypeScript error

`src/server/http/server.ts` used the DOM library's `TransformStream` type with a stream from `Readable.toWeb()`, whose type comes from Node's own web-stream definitions. The two types are not compatible, so `npm run typecheck` failed. The fix imports `TransformStream` from `node:stream/web`. At run time it is the same class (`globalThis.TransformStream === require('node:stream/web').TransformStream` in Node 22), so behaviour is unchanged.

## 3. Formatting only

`src/server/services/documents/parse.ts`: the 7 October PDF font-path fix was re-indented and given a comment. The code is the same.
